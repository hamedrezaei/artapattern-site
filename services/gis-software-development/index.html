What I build

GIS is a software problem, not only a map

The value of a map comes from the system behind it: the data model, the spatial queries, the workflows that use location, and the apps people carry into the field. I approach GIS as backend and architecture work first.

  • 01

    WebGIS applications

    Browser-based GIS for municipal services and emergency response, including damage and aid estimation and nearest-facility analysis.

  • 02

    Spatial data and queries

    Spatial queries and stored procedures in SQL Server, PostgreSQL synchronization, and property maps tied to business workflows.

  • 03

    Field and mobile apps

    Android and Kotlin apps with offline maps, tracking and photo or video capture; offline tile caching with MapProxy.

  • 04

    Desktop GIS and CAD integrations

    ArcGIS plugins with Oracle synchronization, ArcEngine vehicle tracking, and AutoCAD automation for land-parcel boundaries.

FAQ

Common Questions

Do you build WebGIS applications?

Yes. I have built and contributed to WebGIS applications for municipal platforms, emergency response and sales distribution, using ASP.NET, Django and PostgreSQL.

Can you add maps and spatial queries to an existing .NET system?

Yes. On a municipal platform I optimized SQL Server spatial queries, stored procedures and triggers, and tied requests and cases to property maps.

Do you build field apps that work offline?

Yes. I have built Android apps with offline maps for city data collection, and offline tile caching with MapProxy.

Do you work with ArcGIS?

Yes. I have developed ArcGIS plugins synchronized with an Oracle database and ArcEngine-based Windows applications for vehicle tracking.
