01 / Project overview

Dealing-desk logic inside the trading server

A C++ plugin for MetaTrader servers that adds dealing-desk behavior with configurable, broker-oriented slippage management, built alongside other broker-specific plugins.

02 / Engineering context

Engineering context

Server-side MetaTrader plugins run inside the trading server process, so correctness and careful testing matter more than usual: a defect affects order handling directly.

03 / Problem & constraints

Problem & constraints

  • The plugin runs inside the MetaTrader server process, so correctness comes before features.
  • It had to integrate with both MT4 and MT5.
  • Slippage behavior had to be configurable by the broker.
  • Architecture, implementation, configuration, debugging and testing were owned by one engineer.
04 / Architecture approach

A configurable server-side plugin

The plugin sits in the server's order flow and applies broker-defined slippage rules, with configuration kept separate from code so behavior can be adjusted without rebuilding.

05 / Key engineering decisions

Key engineering decisions

DECISION 01

Keep rules configurable

Slippage behavior is driven by broker configuration rather than hard-coded values, so policy changes do not require a new build.

DECISION 02

Test before integration

Behavior was verified before connecting the plugin to MT4/MT5 servers, because a defect inside the server affects order handling directly.

DECISION 03

Keep the engineering boundary clear

I owned architecture, implementation, configuration, debugging, testing and MT4/MT5 integration; the slippage policy itself remains the broker's decision.
