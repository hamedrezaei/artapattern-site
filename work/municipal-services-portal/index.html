01 / Project overview

Public services on a shared platform

Two products on the same municipal automation platform: a services portal where requests, payments and property information come together, and Building Violation Commission software that carries a case from registration through calculation to a digitally signed decision.

02 / Engineering context

Engineering context

These are two products on the same platform as the Enterprise Platform Modernization case study: that case covers migrating five related subsystems to .NET 7; this one covers delivering new, citizen-facing products on the platform. They depended on the same workflows, spatial data, reporting and signature infrastructure as the rest of the platform, so changes had to fit the platform rather than work around it.

03 / Problem & constraints

Problem & constraints

  • Payments and financial calculations had to be correct and traceable.
  • Decisions needed digital signatures before they took effect.
  • Every request and case had to be tied to a property and its spatial data.
  • Both products had to integrate with the existing platform subsystems and reporting.
04 / Architecture approach

Compose from platform capabilities

Requests and commission cases were modeled as workflows on the shared platform. Property maps came from the platform's WebGIS layer, calculations and reporting ran against the same SQL Server data, and decisions were closed with digital signatures, so each case kept one consistent record from submission to signed outcome.

05 / Key engineering decisions

Key engineering decisions

DECISION 01

Use the platform's workflows instead of new ones

Requests and violation cases followed the same workflow model as the rest of the platform, so staff and support worked with one consistent process.

DECISION 02

Anchor every case to a property

Linking requests and cases to property maps kept spatial data, calculations and decisions aligned.

DECISION 03

Close decisions with digital signatures

Signed decisions gave each case a clear, verifiable end state.
