MetaTrader Plugin Management Platform

01 / Project overview

A control plane for broker-side plugins

The platform manages MetaTrader server plugins for a brokerage: it holds their configuration and licences centrally, exposes an administration interface, and keeps the components running on the customer side in sync with what the backend says they should be.

02 / Engineering context

Engineering context

The work sat inside a forex brokerage's engineering team, alongside C++ MetaTrader plugins and other broker-specific integrations. The platform was taken from concept to a first released version by one engineer, which made explicit structure and automated verification essential.

03 / Problem & constraints

Problem & constraints

  • Plugin configuration and licensing had to be managed from one place.
  • Runtime components live on customer-side infrastructure, outside direct control of the backend.
  • One engineer owned architecture, implementation and release, so the design had to stay small and verifiable.
04 / Architecture approach

Desired-state architecture

The backend acts as a control plane: it records the desired configuration and licence state for each runtime. Customer-side runtime components report their status and converge on that desired state, so configuration changes and licensing are centralized without the backend reaching into customer infrastructure.

05 / Key engineering decisions

Key engineering decisions

DECISION 01

Separate the control plane from customer-side runtimes

Central configuration and licensing, with runtime components converging on a recorded desired state.

DECISION 02

Model the domain before the services

Domain and data modeling came first so licensing, configuration and runtime status had clear owners.

DECISION 03

Verify every release automatically

Automated tests and regression verification produced release evidence for each version.
