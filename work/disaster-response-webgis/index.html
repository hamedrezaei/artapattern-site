01 / Project overview

Spatial decision support for disaster response

A WebGIS built for a national humanitarian relief organization to support earthquake response: estimating damage, estimating aid requirements, and identifying the help stations nearest to affected areas.

02 / Engineering context

Engineering context

This was part of my early career as a GIS developer. Requirements were worked out directly with project owners. In the same role I also built ArcGIS plugins synchronized with an Oracle database, a separate project listed in the archive.

03 / Problem & constraints

Problem & constraints

  • Results had to be usable by response staff in a browser, not only by GIS specialists.
  • Damage and aid estimates depended on combining several spatial datasets.
  • Finding the nearest help stations required proximity analysis on the map data.
04 / Architecture approach

Analysis on the map, delivered through the browser

Spatial data and estimation logic were brought together in a web-based GIS, so coordinators could see an affected area, its estimated damage and aid requirements, and the nearest help stations in one view.

05 / Key engineering decisions

Key engineering decisions

DECISION 01

Deliver GIS through the web

A WebGIS put the analysis in front of response staff without desktop GIS software.

DECISION 02

Combine estimation with proximity

Damage and aid estimates were shown together with the nearest help stations to support response planning.
