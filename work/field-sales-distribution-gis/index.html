Case study 05 · GIS Integration / Field Operations · 2012 – 2015

Field Sales & Distribution Platform

Led an ASP.NET MVC sales-assistance application for product distribution and order management, integrating tracking, spatial queries and a mobile API layer, after earlier work on WebGIS and Android sales-management tools.

01 / Project overview

Putting sales operations on the map

Two consecutive roles on the same problem: giving distribution companies tools for remote order entry, product distribution, field data collection and tracking. The later sales-assistance application, which I led, brought order management, tracking and spatial queries into one ASP.NET MVC system with a mobile API.

02 / Engineering context

Engineering context

Field staff worked away from the office, so orders and visit data were captured on mobile devices and sent to a central web application. Location was part of the data, which made spatial queries and map views core features rather than extras.

03 / Problem & constraints

Problem & constraints

  • Order entry and data collection happened in the field, on mobile devices.
  • Distribution and tracking data had to be queried by location.
  • Web and mobile clients had to share one consistent set of orders and records.
04 / Architecture approach

One backend, two kinds of client

The ASP.NET MVC application held orders, distribution and tracking data and offered map views and spatial queries to office users. A separate mobile API layer gave field apps a stable contract for submitting orders, collected data and location.

05 / Key engineering decisions

Key engineering decisions

DECISION 01

Give mobile clients their own API layer

Field apps used a dedicated API instead of the web application's pages, keeping the mobile contract stable.

DECISION 02

Treat location as core data

Tracking and spatial queries were built into the data model so distribution could be viewed and analyzed on the map.
